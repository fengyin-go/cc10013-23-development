# API数据聚合采集中心

面向多源API接入、接口编排、数据聚合、响应校验、频率控制与数据转储的API数据聚合采集中心。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

### 指标联合窗口（metric_window）

采集指标不再按单指标独立处理，三项指标（成功率、延迟、错误率）按「指标编号 + 时间窗」
组成联合窗口，联合计算后每个窗口只保留一个可解释结论：

- **三张数据集**：`metric_sample`（采集指标样本，原始证据）、`metric_window`（联合窗口，
  含窗口身份、判定版本、发布快照与版本记录）、`metric_todo`（指标待办队列）。
- **联合计算**：三项样本到齐才发布联合结论（v1）；窗口区分「样本引用」（当前结论依据的
  三项生效样本）与「全部样本」（含迟到样本），复测生成新判定版本并分别引用三项样本。
- **发布留档**：首次发布时把结论、引用与三条样本整体快照保存，后续复测/裁决只追加版本记录。
- **迟到裁决**：结论发布后到达的样本只追加不改写，自动生成高优先级「迟到裁决」待办；
  裁决「维持原结论」则生效引用不变，「采纳更正」才用迟到样本替换对应指标引用，
  裁决后进入「终态裁决」，窗口始终只有一个结论。
- **待办队列**：异常窗口与迟到冲突收存为待办，按「待处理优先、高优先级先行」排序，
  支持指标编号/端点搜索、优先级与状态筛选、分页。
- **可回溯**：结果详情的指标编号与时间窗可回到每条原始样本，迟到与未生效样本单独标出，
  异常端点联动标红；样本列表支持按指标编号搜索、异常筛选与分页，可定位回同一窗口。
